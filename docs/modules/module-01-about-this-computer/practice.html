Module 1 Practice

Module 1 — About This Computer · For students

For students. Do each lesson’s practice after that lesson. Read first: predict before you run anything. Write your answers in your tracing notebook (paper). The prediction box beside the code isn’t saved. If your teacher asks you to hand something in, put your written answers in a comment at the top of your .py file. · Module 1 overview

Save every file in your course folder, in the folder for that lesson.

After Lesson 1: Ask the Computer About Itself

Read and predict

Read this program without running it. Write your answers in your tracing notebook, then type your prediction in the box and press Step.

  1. How many lines will it print?
  2. Which lines will be exactly the same on every computer?
  3. Which parts will change from computer to computer?
  4. Which line of code prints Done?
import platform

print("Python report")
print("System:", platform.system())
print("Python version:", platform.python_version())
print("Done")

Modify

Make each change, predict the new output, then run it.

  1. Add a line that prints the CPU type with the label CPU:.
  2. Change the first line so it prints your name instead of Python report, for example Python report by Sam.
  3. Move print("Done") to the top of the program. What happens? Why?

Make

On your classroom computer (Thonny, IDLE, or VS Code), write a program that prints:

  • a title line, and
  • three labelled facts about the computer: its CPU type, its operating system, and the operating system’s version number (platform.release()).

Run it, then copy its output under your code as a comment.

After Lesson 3: Getting Output Right

Read and predict

Read this program without running it. In your tracing notebook, write the exact output, one line per row. Then type your prediction and press Step.

  1. How many lines will it print?
  2. What character appears between Name: and the computer’s name? How will it look on the screen?
  3. Lines 8 and 9 are two print() calls. Why does their output appear on one line?
  4. Count the characters in lines 4, 5, and 6. Are they all the same width? Why does that matter?
import platform

name = platform.node()
print("+--------------------+")
print("|   LAB INVENTORY    |")
print("+--------------------+")
print("Name:", name, sep="\t")
print("Checked", end=" ")
print("today")

Spot the mistake

Predict what will happen, then press Step.

  1. Does any line run before Python stops? Why or why not?
  2. What kind of error is it, and what does the message say?
  3. Fix the program on your classroom computer and run it.
import platform

print("Operating system:", platform.system()
print("Done")

Modify

Predict each change, then run it.

  1. Change line 3 so the output is CPU type -> wasm32 (on the web page), using sep.
  2. Make lines 4 and 5 print on one line, using end.
  3. Print It's "fast" on its own line. You need both kinds of quotation marks.

After Lesson 4: Better Reports with f-strings

Read and predict

Read this program without running it. In your tracing notebook, write the exact output, showing spaces as dots (·) on the first three lines. Then type your prediction and press Step.

  1. How many characters wide is the first line of output, spaces included?
  2. Why do Emscripten and the Python version start in the same column?
  3. Lines 5 to 7 have quotation marks inside the braces. What do they do?
import platform

system = platform.system()
version = platform.python_version()
print(f"{'LAB REPORT':^20}")
print(f"{'System:':<10}{system}")
print(f"{'Python:':<10}{version}")
print(f"Python {version} is running on {system}.")

Spot the mistakes

This program has two mistakes. Predict what will happen, then press Step.

  1. Line 4 runs without an error, but its output is wrong. What’s missing?
  2. Line 5 stops the program. What kind of error is it: syntax or run-time? How do you know?
  3. Fix both on your classroom computer. (For line 5, use cores = 4 for now. In Module 2 you’ll ask the computer.)
import platform

cpu = platform.machine()
print("CPU type: {cpu}")
print(f"Cores: {cores}")

Modify

Predict each change, then run it.

  1. Right-align the numbers so their last digits line up.
  2. Add a third row for a USB key that holds 64 GB.
  3. Make the label column wide enough for External hard drive.

Make

Rewrite your Lesson 2 report on the classroom computer so it looks like the systeminfo output from Lesson 3: every label padded to the same width with an f-string, so all the values start in one column. Save it as systeminfo_style.py in ics3u/module-01/lesson-04/.

After Lesson 5: Values and Types

Read and predict

Read this program without running it. In your tracing notebook, write the type of each variable, then the exact output. Then type your prediction and press Step.

  1. What three types does line 4 print?
  2. Line 5 multiplies an int by a float. What type is the answer?
  3. Lines 6 and 7 use * and + with a string. What does each do?
  4. What does line 8 print, and what type is it?
cores = 8
speed_ghz = 3.2
name = "LAB-PC-14"
print(type(cores), type(speed_ghz), type(name))
print(cores * speed_ghz)
print(name * 2)
print(str(cores) + " cores")
print(cores > 4)

Spot the mistake

Predict what will happen, then press Step.

  1. Which line stops the program? What kind of error is it?
  2. What is the TypeError message telling you?
  3. Fix it two ways: by changing line 1, and by changing line 3 with int().
storage_gb = "512"
used_gb = 200
free_gb = storage_gb - used_gb
print(f"Free: {free_gb} GB")

Modify

Predict each change, then run it.

  1. What type is photos? Why?
  2. Nobody stores part of a photo. Print the number of photos as a whole number, using int().
  3. Put quotation marks around 4.5. What happens? Why?

Make

A school buys 30 refurbished computers at $219.99 each. On your classroom computer, write a program that prints the cost before tax, the HST (13%), the total, and the cost per computer including tax. Store the price, the number of computers, and the tax rate in variables (the tax rate as a constant), and show every amount to two decimal places. Save it as lab_budget.py in ics3u/module-01/lesson-05/.

After Lesson 6: Where Do My Programs Live?

Read and predict

Read this program without running it. On this web page, the home folder is /home/pyodide. In your tracing notebook, write the exact output. Then type your prediction and press Step.

  1. What does os.path.expanduser("~") give you? (The ~ is short for “my home folder”.)
  2. What will line 7 print here? Would it print the same on your classroom computer?
  3. What type of value does os.path.isdir() give back?
import os

home = os.path.expanduser("~")
course = os.path.join(home, "ics3u")
print("Home folder:", home)
print("Course folder:", course)
print("Course folder exists:", os.path.isdir(course))
print("Last part:", os.path.basename(course))

Spot the mistake

Predict what will happen, then press Step.

  1. What printed before the program stopped? What kind of error is it?
  2. The message mentions int. Which value is the problem?
  3. Fix it two ways: with str(), and by changing line 3.
import os

year = 2026
print("Building the path...")
print(os.path.join("ics3u", "backups", year))

Modify

Predict each change, then run it.

  1. Print just the name of the lesson folder, lesson-06. (Hint: use basename on the result of dirname.)
  2. Build the path to sample-folder/photos inside /Users/sam/ics3u, using os.path.join.
  3. What does os.path.basename("/Users/sam/ics3u/") print? Why?

Make

Where does Python itself live on your computer? On your classroom computer, write where_is_python.py (in ics3u/module-01/lesson-06/) that prints the full path to the Python program that’s running it (sys.executable, after import sys), then the name of the folder it’s in. Run it from your editor and from the terminal. Is it the same Python both times?
