Module 1: About This Computer

About 15 hours · For teachers

The big idea: students ask the computer about itself. They start with one line of Python that prints the processor type and build up to a labelled report stored in variables. Along the way they learn to read, predict, and trace code, use a module’s tools, and read error messages. They also discover that a program reports on whatever computer it actually runs on.

Expectations: A1.1, A2.1, A2.2, A3.1, A4.2, A4.3, A4.4, C1.1, C1.4, C2.1, C3.1, C3.3, C3.4, C3.5 (across the whole module)

Planned lessons

Planned, not yet written. Titles and focus may change as lessons are built.

Lesson Focus Students read, then build
6. Where Do My Programs Live? Files, folders, and paths; organizing a course folder on local and shared drives; the parts of the editor (C2.1, C3.1); first run of the sample folder generator; reading a two-line program that prints the current folder Explain the course folder students set up on day one, then add the toolkit folder; run the same file from the editor and the terminal
7. What Python Actually Runs Source code vs. machine code; interpreters vs. compilers; bytecode with dis; applications vs. languages vs. operating systems (C3.3, C3.4, C3.5) Match dis output to lines of code; sort running programs into apps, languages, and OS parts
8. Inside the Computer: RAM and CPU Where variables live and where arithmetic happens; sys.getsizeof() and id() (C1.1, C1.4) Trace a program and label each line “RAM” or “CPU”
9. Talking Back, and a First Look Ahead Reading a program that greets the user by name with input() and gives a hardware summary (A2.1); then reading a simple if (“if this is Windows…”) and a for loop over a list of facts Modify the greeter; predict the if program’s output on three operating systems
10. Error Clinic Syntax and run-time errors; reading a traceback from the bottom up (A4.3, A4.4) Fix five broken report programs
11. Review and assignment work period A short review game on Lessons 1–10, then class time for the assignment Finish the Computer Report Card
12. Module 1 test Code reading and tracing; a short basics section

Each lesson plan’s Code for This Lesson section has the .py files and notebooks. Students find the same files at the end of each lesson’s section on the Practice page.

Assignment

Computer Report Card (ready for Lessons 1–2; will grow with the module). Students read and trace a short program, write a report card using five platform functions stored in variables, then run it in two places and explain the difference. Students hand in one .py file built from a starter file.

Planned additions: an f-string version of the report, a short input() greeting, and a written part explaining what happens inside the computer when the report runs (RAM, CPU, interpreter).

Adds to the toolkit: report_card.py, the first file in the student’s My Computer Toolkit folder, which grows in every module (see the toolkit thread).

Practising the Basics (Planned)

  • Skill Builder: short drills on print() arguments, sep and end, escape characters, quotes, variables, types, f-strings, and reading a traceback. Each drill set opens with predict-the-output and fix-the-error questions.
  • Quick Builds (small graded programs; each is the Make product of a lesson, so it needs no extra period):
    • System Banner (Lesson 3): a boxed title banner for the computer, with exact spacing.
    • Parts Receipt (Lesson 5): a receipt for computer parts, with prices, HST, and a total in aligned columns.

Until the Skill Builder is ready, use the Practice page and the exit tickets for retrieval practice.

How Module 1 Fits

  • Before: nothing. This is the first module; students need no programming experience.
  • Planned for the rest of the module: see Planned lessons above, and the Scope and Sequence.
  • Next: Module 2, Spec Checker, adds os and shutil to check whether a computer meets a program’s requirements.
  • Students set up first: their course folder, before Lesson 1’s Make.
