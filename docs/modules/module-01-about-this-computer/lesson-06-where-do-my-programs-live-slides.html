Where is this program?

import os

print(os.getcwd())

Open with the problem: “Hands up if you’ve saved something and couldn’t find it. When your program runs, where is it, and what can it see from there?” Run it on the classroom computer too. TEACHER PROMPT (paths): “os talks to the operating system. getcwd() means get current working directory; directory means folder. The answer is a path: the address, folder by folder from the top of the drive. Windows uses backslashes and a drive letter; macOS and Linux use forward slashes. On this page it’s /home/pyodide: a folder inside the browser’s virtual computer. Lesson 1 again.”

Every file has an address

/Users/sam/ics3u/
├── module-01/
│   ├── lesson-06/
│   └── assignment/
│       └── report_card.py
└── toolkit/
  • Full path: /Users/sam/ics3u/module-01/assignment/report_card.py
  • Relative path (from module-01): assignment/report_card.py

Trace both paths with a finger. Windows: C:3u... A relative path starts from the current folder.

Predict, then step

import os

folder = os.getcwd()
print("Running in:", folder)
print("This folder's name:", os.path.basename(folder))
print("The folder it's inside:", os.path.dirname(folder))
print(os.path.join(folder, "toolkit", "report_card.py"))

About 10 minutes. Ask: what will each line print here? What do basename and dirname do? Does report_card.py have to exist for line 7? “os.path.join glues folder names together with the right slash for the computer it runs on. It only builds the address; it doesn’t check whether anything lives there.”

The parts of your editor

Part What it’s for
Code editor Writing and saving the program
Shell or terminal Output; typing one line of Python
Run button Saves and runs
Debugger One line at a time, showing variables
File browser Folders and files

Students copy the table and find each part in their own editor. TEACHER PROMPT (debugger): “Step-through boxes are a simple debugger. Your editor has a real one: Thonny’s bug button, IDLE’s Debug > Debugger, VS Code’s Run and Debug. Try it on l06_paths.py.”

Run it from the terminal

  1. Open a terminal
  2. cd ics3u
  3. Save make_sample_folder.py in ics3u, then read the comment at the top
  4. python3 make_sample_folder.py (Windows: py make_sample_folder.py)
  5. Where did sample-folder appear? Why there?

TEACHER PROMPT (terminal): “The terminal has a current folder too. cd means change directory. To run a program, type python3 (Windows: py) and its name; it starts in the terminal’s current folder. Nothing here can break the computer.” Then: run l06_where_am_i.py from ics3u: python3 module-01/lesson-06/l06_where_am_i.py. It prints ics3u’s path, not lesson-06’s. “The current folder is where you started the program, not where the file lives. That’s why sample-folder appeared inside ics3u.”

Spot the problem

import os

print("Looking for the toolkit...")
print(os.listdir("toolkit"))

Run-time error (line 3 printed). FileNotFoundError: there’s no toolkit folder in the current folder (here /home/pyodide; Errno 44 in the browser, Errno 2 on a real computer). Ask: the same file works when run from ics3u but crashes when double-clicked in lesson-06. Why?
