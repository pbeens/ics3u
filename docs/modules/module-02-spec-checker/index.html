Module 2: Spec Checker

About 15 hours · For teachers

Planned module. This page shows the direction for Module 2. Lessons, slides, and practice pages are not written yet.

The big idea: students decide whether a computer meets someone’s needs. They measure the classroom computer (cores, storage, free space), turn raw numbers into sizes people understand, and write programs that answer real questions: Is there room for this download? Will this game run? Which laptop suits this person?

Why students care: every student has stood in a store, or on a website, wondering which computer to buy, or why their “1 TB” drive shows only 931 GB. This module answers those questions with code.

Expectations: A1.1, A1.3, A1.4, A2.1, A2.2, A4.1, A4.3, A4.5, B1.1, B1.3, B2.5, B3.2, B3.3, B4.4, C1.1, C1.2, C1.3

Anchor Programs

  • Core counter: os.cpu_count(), then a report of what the cores mean for multitasking.
  • Storage calculator: bytes to kilobytes, megabytes, and gigabytes; why manufacturers and operating systems disagree (1000 vs. 1024).
  • Drive gauge: shutil.disk_usage() reports total, used, and free space, with a percentage and a warning level.
  • Will This Game Run? compares this computer to a game’s published minimum requirements.
  • Screen sharpness calculator: pixels per inch from a monitor’s resolution and size (the hypotenuse formula, B3.2).

Assignment (Planned): Will It Run?

Students pick a real game or app with published minimum requirements. Their program:

  1. Reads what it can from the computer (operating system, CPU type, cores, free storage).
  2. Asks the user for what Python can’t find (RAM, graphics card).
  3. Reports each requirement as pass or fail, with a clear summary and friendly messages for bad input.

They also hand in a test plan (normal, boundary, and invalid cases) and a one-paragraph recommendation: should this person upgrade, and what?

Adds to the toolkit: drive_check.py: storage and core checks with warning levels, reused by later modules.

Practising the Basics (Planned)

  • Skill Builder: input() and type conversion, arithmetic operators and order of operations, comparisons, if/elif/else, and try/except. Includes Module 1 print() and f-string review.
  • Quick Builds (small graded programs; each is the Make product of a lesson, so it needs no extra period):
    • Storage Unit Converter (Lesson 2): bytes, KB, MB, GB, and TB in both directions.
    • Battery Life Estimator (Lesson 5): battery capacity and power draw in, hours of use out, with a warning for impossible values.
  • Warm-ups in every lesson include a question from an earlier module.

Notes for Teachers

  • One new module at a time: os.cpu_count() first, then shutil.disk_usage() a lesson later, following Module 1’s pacing.
  • RAM: the standard library can’t report total memory. Treat that as a teaching point: some answers must come from the user, the system settings, or the manual.
  • Real numbers: bring in actual spec sheets and game requirement pages. Students should see the vocabulary of C1.2 (processor type, storage capacity, memory) in the wild.

How Module 2 Fits

  • Before: Module 1 taught import, print(), variables, and reading errors, and let students read their first if and input().
  • Next: Module 3, Benchmark Lab, measures how fast the computer is, using loops.
  • Then: the Computer Science in the World lesson Who Builds Computers? (about 1 hour), before Module 3.
